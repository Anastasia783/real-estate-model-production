# Monitoring

Сервис предсказания стоимости недвижимости (ml_service) отдаёт метрики на эндпоинте /metrics. Prometheus собирает их с цели ml_service:8000, а Grafana показывает на дашборде Real Estate ML Service (uid real-estate-ml-service, datasource prometheus). Дашборд подключается автоматически через provisioning из services/grafana/dashboards/real-estate-ml-service.json. Копия модели дашборда и скриншот лежат в services/dashboard.json и services/dashboard.jpg.

## Как запустить 

docker compose --env-file services/.env up -d --build
python scripts/load_test.py --requests 600 --delay 0.2
Сервис: http://127.0.0.1:8000
Prometheus: http://127.0.0.1:9090 (Status -> Targets, цель ml_service должна быть UP)
Grafana: http://127.0.0.1:3000 (admin / admin), дашборд Real Estate ML Service

Скрипт нагрузки отправляет корректные запросы на /predict и часть некорректных, чтобы на дашборде появились ответы со статусами 200 и 422.

## Прикладные метрики
Показывают, как сервис работает для клиентов.

http_requests_total (метки: method, path, status) показывает число HTTP-запросов по эндпоинтам и кодам ответа.
http_request_duration_seconds (метки: method, path)	показывает 	время обработки запроса, по ней считается p95 задержки.

Вопросы, на которые отвечают метрики: сколько запросов получает сервис, как быстро он отвечает, какая доля запросов завершается ошибкой клиента (422) или сервера (5xx).

## Инфраструктурные метрики

Показывают, жив ли сервис и доступен ли он для мониторинга.

up{job="ml_service"} - Prometheus успешно опросил цель ml_service:8000 (1 - да, 0 - нет)

Эндпоинт /health отвечает HTTP 200, если сервис запущен и модель загружена. Запросы к нему исключены из графика нагрузки

## Мониторинг модели
Показывают, как ведёт себя сама модель и какие данные ей приходят.

model_prediction_value_rub	показывает распределение предсказанных цен в рублях
model_input_total_area_m2	показывает распределение общей площади во входных данных
model_prediction_errors_total	показывает число ошибок при получении предсказания

Вывод: резкий сдвиг средней цены или площади при стабильном потоке запросов указывает на изменение входных данных или на проблему в модели. Рост ошибок означает, что модель не справляется с запросами.

## Панели дашборда и выбор визуализаций

1.Запросы в секунду	 - ТИП: timeseries, показывает нагрузку на сервис во времени, видны всплески и провалы

2.Задержка p95, с	- ТИП: timeseries, показывает время, в которое укладываются 95% запросов

3.Средний прогноз в руб.- ТИП: timeseries, показывает динамику средней предсказанной цены

4.Средняя площадь в квадратных метрах- ТИП: timeseries, показывает динамику входных данных; сравнивается с прогнозом
5.Ошибки модели за час - ТИП:stat, показывает число: порог красного цвета при значении от 1
6.Запросы по статусам - ТИП:barchart, показывает сравнение числа ответов 200 и 422 за выбранный период

Такие типы графиков были выбраны, потому что:
timeseries - для величин, которые меняются во времени (нагрузка, задержка, средние значения): видны тренды и всплески.
stat - для критичного показателя, который должен быть заметен сразу
barchart - для сравнения категорий за период, где важно соотношение, а не динамика.

Метрика http_requests_in_progress собирается, но на дашборде не выведена: дашборд содержит 6 панелей.

Дашборд обновляется каждые 10 секунд, период по умолчанию - последние 15 минут.
